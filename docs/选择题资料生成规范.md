# 认词选择题资料生成规范（v1.0）

> 这份文档写给**生成题源的人或模型**，也写给**审这份题源的人**。
> 目标：让「看英文选中文」（认词）成为一种真的能学到东西的练习，而不是四选一的抽奖。
>
> 配套工具：`scripts/quiz.mjs`（提示词 / 校验 / 合并 / 抽样）、`scripts/quiz-lib.mjs`（校验规则源码）。
> 本规范的**机器可判**部分由 `quiz-lib.mjs` 强制执行；**语义质量**只能靠下面第 4、5 节的标准人工抽查。

---

## 1. 为什么要这么做

刷词的默认答法是**拼写**（看中文/听音写单词）。但实际使用中，一个词库里真正需要"会写"的只是少数，
大多数词只要**看到能认出来**就够了。所以增加了**认词**：看英文单词，从 4 个中文释义里选一个。

认词题的质量几乎全部取决于**干扰项**（那 3 个错误选项）：

- 干扰项选得随便 → 一眼就能排除 → 练了等于没练（这是自动兜底生成的典型问题）；
- 干扰项选得讲究 → 每个错误选项都对应一种**真实的混淆**（同词根、形近、近义、词性）→
  答对是"真认识"，答错则通过**辨析**当场把混淆点讲清楚。

所以这份规范的重点不是"输出 JSON"，而是**怎么挑干扰项、怎么写辨析**。

## 2. 数据流

```
public/data-N.json      词库（唯一数据源，人工维护，3568 词 / 22 章）
        │
        ├── public/quiz-N.json     ← 本规范的产物（干扰项 + 辨析 + 只认不拼标记）
        │        │
        │        └── 由 scripts/quiz.mjs 校验；校验失败会被剔除，不进清单
        │
        ├── public/quiz-index.json ← 清单（哪些章有题源），由 quiz.mjs 生成，不要手改
        │
        └── public/quiz.js         ← 前端出题：优先用精编干扰项，没有就用同章词自动生成兜底
```

**关键约定：题源缺失、损坏、校验失败，都不能让练习功能坏掉。**
前端永远有兜底：拿不到 `quiz-N.json` 就用同章词按 `public/quiz.js` 的算法现挑干扰项。

## 3. 文件格式

一个文件对应一章：`public/quiz-N.json`（N = 章号，必须与 `data-N.json` 一致）。

```json
{
  "spec": "1.0",
  "chapter": 1,
  "source": "model",
  "generator": "deepseek-chat",
  "updatedAt": "2026-01-01",
  "items": {
    "1": {
      "need": "spell",
      "note": "atmo（气体）+ sphere（球）→ 包住地球的气体层",
      "distractors": [
        { "text": "水圈；大气中的水汽", "kind": "root", "why": "hydro- 是“水”，指地球上的水体总和" },
        { "text": "岩石圈", "kind": "root", "why": "litho- 是“石”，指地壳的岩石部分" },
        { "text": "半球", "kind": "form", "why": "hemi- 才是“一半”，与“气体”无关" }
      ]
    }
  }
}
```

### 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `spec` | 建议 | 规范版本，当前 `"1.0"`。不一致只会警告 |
| `chapter` | **必填** | 章号，必须等于文件名里的 N |
| `source` | 建议 | `model` / `human` / `model+human` |
| `generator` | 建议 | 生成模型名（便于回溯与重跑） |
| `updatedAt` | 建议 | `YYYY-MM-DD` |
| `items` | **必填** | 键 = **词库里的 id**（字符串化的整数）；值是下面的 item |

### item 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `distractors` | **必填** | **恰好 3 条**（4 选 1）。见第 4 节 |
| `distractors[].text` | **必填** | 干扰项的中文释义。**必须是中文**，不要抄英文、不要写解释句 |
| `distractors[].kind` | **必填** | `root` / `form` / `pos` / `sense` / `topic` / `antonym` 之一 |
| `distractors[].why` | **必填** | 一句辨析，≤40 字。见第 5 节 |
| `note` | 可选 | 词根拆解或记忆钩子，≤60 字。答对时展示 |
| `need` | 可选 | `spell`（默认，别写）/ `read`（只认不拼）。见第 6 节 |

> **id 必须以 `data-N.json` 为准**：id 是前端定位词、同步学习状态的唯一键。
> 自己重新编号 = 全部题源作废（校验器会直接判错）。
> 释义也**不要**自己改写：`text` 只描述"干扰项"，正确释义永远取自词库。

## 4. 干扰项设计规范

### 4.1 六种类型（kind）与配额

| kind | 含义 | 什么时候用 | 配额 |
| --- | --- | --- | --- |
| `root` | **同词根**：共享一个 ≥3 字母的拉丁词根 | `root` 字段里出现同一个词根 token（`hydrosphere` / `lithosphere` 共享 `sphere`） | 不限，**每题最好 1~2 个** |
| `form` | **形近/音近**：前缀 ≥3 或后缀 ≥4 相同 | `adapt` / `adopt`、`carbon dioxide` / `oxide` | 不限 |
| `sense` | **近义**：释义用词高度重合，但范围/程度/搭配不同 | `say` / `speak` / `tell` 类 | 不限 |
| `pos` | **词性不同**：考"看词性" | 目标词是 `n.`，干扰项是 `v.`/`adj.` | **最多 1 个（机器强制）** |
| `topic` | **同主题**：本章相关但不是这个词 | 凑数用，保证 4 个选项"气质"一致 | **最多 2 个**（机器强制） |
| `antonym` | **反义** | 反义词恰好在同章（`increase` / `decrease`） | **最多 1 个（机器强制）**，太容易排除，别多用 |

**机器强制的两条**（只针对你交付的题源；前端"自动兜底生成的干扰项"是另一套逻辑）：

1. `topic` 最多 2 个；
2. 每题**至少 1 个**有辨析价值的干扰项（`root` / `form` / `sense` / `antonym`）——
   三个全是"同主题不同概念"等于没出题。

### 4.2 好干扰项的四个标准

1. **同层级**：都是本章的词、语义范畴相近。不要出现"苹果 / 量子力学 / 碳酸钙"这种量级差。
2. **可辨析**：你能用一句话说清它和目标词差在哪（词根、词性、搭配、程度、方向）。
3. **不歧义**：任何学习者都不会认为它**也**正确。凡是"其实也对"的，一律不能用。
4. **不作弊**：长度与正确释义接近（在 0.5x ~ 2.0x 之间）；
   不要同一批题里反复用同一个"万能干扰项"。

### 4.3 红线（校验器会判错，别踩）

1. 干扰项与正确释义**重复或互相包含**（`大气层，大气圈；气氛` 对 `气氛`）→ 两个选项都说得通。
2. 同一题内的两个干扰项互相包含 / 完全重复。
3. `distractors` 不是恰好 3 条。
4. `kind` 不在六种里。
5. 缺 `why`，或 `why` 超过 40 字。
6. 三个干扰项全是 `topic`（没有可辨析项）。
7. `topic` 超过 2 个。
8. `id` 不在 `data-N.json` 里。
9. `need` 不是 `spell` / `read`。
10. `note` 超过 60 字。
11. `text` 不含中文字符（必须是中文释义）。
12. `why` 命中空话黑名单（见附录 A）。
13. 选项的**义项集合被正确释义覆盖**（换序、改写也算同一个意思，如「持久的；耐用的」对「耐用的，持久的」）——机器判错（`senseCover`）。

### 4.4 会被警告（不判错，但会被要求改）

- **万能干扰项**：同一个释义在同一章被 ≥3 个词当作干扰项（校验器按章统计并警告）；

- 覆盖率低于 50%（其余词会退回自动生成）；
- 某干扰项长度不到正确答案的 50% 或超过 200%（"最长的那个就是答案"）；
- 全章 60% 以上的题"正确答案是最长的选项"；
- 同一句 `why` 被复用 ≥3 次（模板句）；
- 标记为 `read` 的词超过本章精编词数的一半。

### 4.5 明令禁止的写法

| 禁止 | 反例 | 为什么 |
| --- | --- | --- |
| "都不对/都对"类选项 | `以上都不是` | 不是释义，破坏 4 选 1 |
| 空泛干扰项 | `另一个意思`、`错误的选项` | 学习者排除它学不到任何东西 |
| 用同义词充当干扰项 | `愉快` 对 `高兴` | 两个都算对 = 歧义 |
| 用词性/释义包含关系 | `行为` 对 `行为；功绩；契约` | 包含关系 = 两个都说得通 |
| 超长解释句 | 把 `why` 塞进 `text` | 长度会暴露答案，且选项读起来不像选项 |
| 英文或拼音释义 | `atmosphere`、`dàqìcéng` | 选项必须是中文释义 |
| 与本章毫无关系的词 | 从别的章随便抓 | 一眼排除，且破坏"同层级" |
| 事后只替换 text | 修复脚本把干扰项的 `text` 换掉却保留 `why`/`kind` | 辨析与选项错位（历史事故 916 条的根因）；text/why/kind/note 必须同一次产出 |
| 自己改写正确释义 | 把 `大气层，大气圈；气氛` 写成 `大气` | 正确释义只由词库决定，改写会导致歧义判定失效 |

## 5. 辨析（`why` / `note`）写作规范

**辨析是这套题源真正的价值**：答错时页面上会逐条列出每个干扰项的 `why`，
所以它必须**具体到"差在哪"**，而不是复述"这是错的"。

### 5.1 `why` 的三段式

`区分点（词根/词性/搭配/程度） + 这个选项的真实含义 +（可选）怎么记`

字数 ≤40。不要出现"这个词""意思不同""不是这个词"这类空话。

| kind | 好例子 | 差例子 |
| --- | --- | --- |
| `root` | `litho- 是“石”，指岩石圈；atmo- 才是“气”` | `词根不同` |
| `form` | `hemi- 是“一半”，与“气体”无关` | `拼写有点像` |
| `pos` | `affect 是动词（影响），题目要的是名词` | `词性不对` |
| `sense` | `speak 只强调“开口说”，不涉及“说给谁听”` | `意思相近但不是` |
| `antonym` | `decrease 是“减少”，方向正好相反` | `反义词` |
| `topic` | `同属太空主题，指“轨道”不是“大气”` | `另一个词的意思` |

**区分点的粒度要求**：区分点必须具体到能**排除**的程度。"同属经济领域"不能排除任何选项，"侧重'交易'而非'增长'"才能排除。

- ❌ `同属经济领域但含义不同`（所有干扰项都适用）
- ❌ `同主题的另一个词`（对所有 topic 类都成立）
- ✅ `指"交易/买卖"，不是"增长/扩展"`（只能排除这一个选项）

**空话判定**：如果把 why 里的目标词和干扰项互换，句子仍然成立，那它就是空话。

- ❌ "意思不同" —— 互换后还是"意思不同"
- ❌ "同属经济领域但含义不同" —— 互换后还是"含义不同"
- ✅ "litho- 是'石'" —— 互换后不成立（hydro- 不是"石"）

### 5.2 把差例子改成好例子的方法

差：`意思不同`
→ 先问自己："如果学生选了它，他到底混淆了什么？"
→ 差在**词根**就点词根，差在**词性**就点词性，差在**搭配**就点搭配：
好：`litho-（石）构成的词都跟岩石有关，和“气体”无关`

### 5.3 `note`（记忆点）

一句话的词根拆解或记忆钩子，≤60 字，**不要抄例句**：

- 好：`atmo（气体）+ sphere（球）→ 包住地球的气体层`
- 好：`carbon dioxide = 一个碳 + 两个氧 → 二氧化碳`
- 差：`The planet's thick atmosphere traps heat...`（抄例句）
- 差：`这个词很重要，要记住`（没有信息量）

## 6. `need` 字段：哪些词"只认不拼"

- 不写 = `spell`（要会拼，默认）。**绝大多数词都不要写这个字段。**
- 写 `read` 的情况（认识即可，不必会写）：
  - 只用认得的专有名词、地名、机构名；
  - 极低频技术词（拼写难度远大于使用价值）；
  - 学习者明确表示"只求阅读时认得"的学术词。
- 影响：`read` 的词**不会进入拼写牌堆**（选择题照常出现），也就是说它只影响练习范围，不影响评分。
- 建议：每章 `read` 占比 ≤10%；标多了会被校验器警告（多半是误标）。

## 7. 生成流程

```bash
# 1) 生成提示词（分片，建议每片 40~60 个词，太长模型会偷懒）
node scripts/quiz.mjs prompt 21 --limit 50 --out prompt-21-1.md
node scripts/quiz.mjs prompt 21 --offset 50 --limit 50 --out prompt-21-2.md

# 2) 把 prompt-21-1.md 贴给模型（任何模型都行），把返回的 JSON 存成
#    content/quiz/21-1.json

# 3) 合并 + 校验（有错不会写入；--dry-run 只看结果）
node scripts/quiz.mjs merge content/quiz/21-1.json --chapter 21

# 4) 抽查：打印"用户在页面上会看到的那道题"（同一套算法与随机种子）
node scripts/quiz.mjs sample --chapter 21 --count 8

# 5) 全部章节体检（并重建 quiz-index.json）
node scripts/quiz.mjs check
```

要点：

- **分片提交**：一片 40~60 词，先合并一片跑一次 `check`，别一次生成 400 个词。
- **同一 id 后写覆盖先写**：想改某个词，重新生成它所在的分片再 `merge` 即可。
- **`public/quiz-index.json` 由工具生成**，不要手改；没有题源的章节前端不会去请求。
- 提交代码即可，GitHub 集成会自动部署（约 1 分钟）；部署后 `npm run verify:live` 看线上。

## 8. 交付前自检清单（逐条打勾）

- [ ] 每个 id 都来自 `data-N.json`，没有自造 id、没有漏 id
- [ ] 每个词恰好 3 个干扰项，字段齐全（`text` / `kind` / `why`）
- [ ] 每题至少 1 个 `root`/`form`/`sense`/`antonym`，`topic` ≤2，`pos` ≤1
- [ ] 逐条检查过"有没有两个选项都说得通"（包含关系、同义词）
- [ ] 每条 `why` 都点名了区分点，字数 ≤40，没有空话
- [ ] 干扰项长度与正确释义接近，没有"最长的是答案"
- [ ] 输出是纯 JSON，`node scripts/quiz.mjs merge` 校验通过
- [ ] `node scripts/quiz.mjs sample --chapter N --count 8` 抽看过，辨析讲得通
- [ ] 如标了 `need:"read"`，确认是有意为之且占比 ≤10%
- [ ] 干扰项 `text` 不含英文/拼音
- [ ] 干扰项 `text` 不含解释句（"是指""意思是"）
- [ ] 没有"以上都不是"类选项
- [ ] `pos` 类干扰项 ≤1 个/题
- [ ] `antonym` 类干扰项 ≤1 个/题

## 9. 验收标准

| 项目 | 标准 |
| --- | --- |
| 机器校验 | `node scripts/quiz.mjs check` 无 error（warning 需逐条判断） |
| 覆盖率 | 单章 ≥80% 词有精编题源（不足 50% 会被警告） |

| 上线 | 部署后 `npm run verify:live` 全绿；认词模式能正常出题、辨析正常显示 |

## 10. 兜底算法做了什么（了解边界）

没有精编题源时，`public/quiz.js` 会从**同一章**的词里按分数挑干扰项：

- 同词根 `+6`；**只差一个字母（等长，如 adapt/adopt）** `+5`；形近（前缀 ≥3 或后缀 ≥4）`+4`；近义（释义二元组重合 ≥0.34）`+3`；词性不同 `+2`；同主题 `+1`；
- 释义长度接近 `+1`；挑选时先满足 `topic` ≤2、`pos` ≤1，**实在凑不满 4 个选项才放宽配额**
  （宁可类型单一，也不能出现 3 选 1 这种缺项题）；
- 硬性排除：与正确释义重复/包含、与已选干扰项重复/包含、同词形（`act`/`acts`）、与正确释义同词形前缀；
- 选项位置用 `chapter:word` 做随机种子打乱 —— **同一题每次进入选项位置完全一致**（不会跳位）。

所以兜底版**能保证不出现"两个都对"**，但它的干扰项只是"统计上像"，缺少语义判断。
精编题源的价值就在于补上第 4、5 节的语义部分 —— 尤其是那些**兜底算法看不到的混淆**（搭配、语域、程度）。

你是一名英语词汇教研员。下面给你一批雅思核心词（`id` / `word` / `pos` / `meaningCN` / `root`）。
请为**每一个词**产出 3 个中文干扰项（连同正确释义共 4 选 1），并为每个干扰项写一句**辨析**，
说明"选了这个的人混淆了什么"。

## 输出（只输出 JSON，不要 markdown 代码围栏以外的解释）

```json
{
  "spec": "1.0",
  "chapter": <章号>,
  "source": "model",
  "generator": "<你的模型名>",
  "items": {
    "<词库里的 id>": {
      "need": "spell",
      "note": "词根拆解或记忆钩子，≤60 字，可省略",
      "distractors": [
        { "text": "干扰项中文释义", "kind": "root", "why": "差在哪，≤40 字" },
        { "text": "干扰项中文释义", "kind": "form", "why": "差在哪，≤40 字" },
        { "text": "干扰项中文释义", "kind": "topic", "why": "差在哪，≤40 字" }
      ]
    }
  }
}
```

## 硬性规则（违反直接判错，会被打回）

1. `id` 必须与给定词表**完全一致**，不要自造编号、不要漏词。
2. 每个词**恰好 3 个**干扰项；每项都有 `text`（中文释义）、`kind`、`why`。
3. `kind` 只能取：`root`（同词根）、`form`（形近音近）、`pos`（词性不同，每题最多 1 个）、
   `sense`（近义但范围/程度不同）、`topic`（同主题不同概念，**每题最多 2 个**）、`antonym`（反义，最多 1 个）。
4. 每题**至少 1 个** `root`/`form`/`sense`/`antonym`，不能三个都是 `topic`。
5. 干扰项**绝对不能**与正确释义重复、包含、或"其实也说得通"。
   例：正确释义 `大气层，大气圈；气氛` 不能出现干扰项 `气氛`（`大气` 也不行）。
6. 干扰项长度要和正确释义接近（0.5~2.0 倍）。不要用超长解释句，不要用"以上都不对"。
7. `why` ≤40 字，必须点名区分点（词根 / 词性 / 搭配 / 程度 / 方向），
   禁止写 `意思不同`、`错误的选项`、`另一个词` 这类空话。同一个句式不要反复用。
8. `note` ≤60 字，是词根拆解或记忆钩子，不要抄例句；不确定就省略。
9. 只有"认识即可、不必会写"的词（专有名词、极低频技术词）才写 `"need": "read"`，
   其余全部省略该字段或写 `"spell"`。每章 `read` 不要超过 10%。
10. **只输出 JSON**，不要输出解释、注释、表格。

## 挑干扰项的方法（这是本题的重点）

对每个词，按下面的顺序找混淆点，凑够 3 个：

1. **同词根**：`root` 字段里出现同一个拉丁词根 token（如 `hydrosphere`/`lithosphere` 共享 `sphere`）。
   这一类最有价值，优先用。
2. **形近音近**：前缀 ≥3 或后缀 ≥4 相同（`adapt`/`adopt`、`oxide`/`dioxide`）。
3. **近义**：中文释义用词高度重合，但范围/程度/搭配不同（`say`/`speak`/`tell`）。
4. **词性不同**：目标词是 `n.` 而干扰项是 `v.`/`adj.`（每题最多 1 个）。
5. **同主题**：本章相关但含义无关的概念（兜底凑数，最多 2 个）。

干扰项的 `text` 应当是**同一个词库里真实存在的词的中文释义**（优先同章），
这样 4 个选项才是同一层级的；不要生造释义。

## 质量示例（照这个标准写）

```json
"1": {
  "need": "spell",
  "note": "atmo（气体）+ sphere（球）→ 包住地球的气体层",
  "distractors": [
    { "text": "水圈；大气中的水汽", "kind": "root", "why": "hydro- 是“水”，指地球上的水体总和" },
    { "text": "岩石圈", "kind": "root", "why": "litho- 是“石”，指地壳的岩石部分" },
    { "text": "半球", "kind": "form", "why": "hemi- 才是“一半”，与“气体”无关" }
  ]
}
```

反例（不要这样写）：
- `{ "text": "气氛", "kind": "sense", "why": "意思不同" }` —— 正确释义里就含"气氛"，且 why 是空话。
- `{ "text": "这不是大气层的意思，大气层是指包围地球的气体层……", "kind": "topic", "why": "错误的选项" }` —— 解释句 + 空话 + 长度作弊。
- 三个干扰项全是 `{ "kind": "topic", "why": "同主题的另一个词" }` —— 没有任何辨析价值。

## 附录 A：空话 why 黑名单

以下 why 模板在机器校验中会被拦截（`quiz-lib.mjs` `WHY_BLACKLIST`）。**黑名单是"已知模式集合"，不是空话的完备判据**——完备判据是 5.1 的互换测试法；每发现新模板句，先进黑名单再修数据：

### 完全空话（任何场景都不允许）

- `意思不同`
- `含义不同`
- `不是这个词`
- `另一个意思`
- `错误的选项`
- `另一个词`
- `词根不同`（没说哪个词根）
- `词性不对`（没说具体词性）
- `拼写有点像`
- `反义词`
- `近义词`

### 模板化空话（句式相同但换了领域名）

- `同属X领域但含义不同`
- `近义但侧重点不同`
- `X.词性，此处需要Y.`
- `但含义不同`
- `但意思不同`

### 判断方法

如果把 why 里的目标词和干扰项互换，句子仍然成立，那它就是空话。

## 附录 B：释义归一化口径

校验器和前端使用 `normalizeMeaning` 函数归一化释义后比较：

- 去除所有空白（空格、全角空格）
- 去除所有标点（，。；、：！？"'""''（）【】《》/|-）
- 转小写

示例：

- `"大气层，大气圈；气氛"` → `"大气层大气圈气氛"`
- `"大气层大气圈气氛"` → `"大气层大气圈气氛"`（视为相同）
- `"气氛"` 是 `"大气层大气圈气氛"` 的子串 → 冲突
