## 4. P2 缺陷：应用导出的备份无法导入（已修复）

- **现象**：访客导出备份 → 改设置 → 导入同一文件 → toast「备份文件格式或版本不受支持」，导入被整体拒绝。
- **根因（写入端与校验端 schema 漂移）**：
  ① 运行时 `daily` 恒有 `resetAt` 字段（`core.js normalizeSettings`/`resetDaily` 都会写），
  而 `validateBackupSettings` 的 daily 白名单没有它 → **所有真实导出必被拒**；
  ② guest 合并路径会产生精简 `resume = { chapter }`（`app.js applyUser`），
  校验器却要求 resume 恰好 7 键 → 该形态同样被拒。
  单测没抓到：`backup-import.test.js` 的造数是手写的理想 payload，不带 `resetAt`。
- **修法**：`validateBackupSettings` 两处放宽到「接受运行时实际形状、逐字段仍严格」——
  daily 白名单加入 `resetAt`（并校验其为非负整数）；resume 改为 `chapter` 必填 + 其余可选逐字段校验
  （仍拒绝未知键，导入侧安全边界不变）。
- **防漂移守卫**：新增单测「backup import accepts settings exactly as the runtime normalizer writes them」，
  直接用 `normalizeSettings()` 的输出作为 payload 断言通过校验（test 217→218）。
- **本地复验**：导出（emerald）→ 改 violet → 导入 → UI 立即回 emerald、localStorage 正确落盘。
