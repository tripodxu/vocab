# docs/agents · 多智能体协作与接力规范

> 目标：多个 agent 可以并行/接力完成同一个需求，而**不互相覆盖、不重复劳动、交接不丢信息**。
> 所有 agent 入场先读根目录 `AGENTS.md`（三层读取法），本文件是协作细则。

---

## 1. 角色划分（一个 agent 可兼任多角色，但产出要齐）

| 角色 | 职责 | 必须交付 |
| --- | --- | --- |
| **Lead（编排）** | 拆任务、分配、裁决冲突、更新看板 | 任务卡、并行边界、最终验收 |
| **执行 Dev** | 按任务卡改代码 | 改动文件清单 + 门禁结果 + 交接说明 |
| **测试 QA** | 补/跑测试与门禁 | 测试文件 + 通过结果 + 发现的缺陷 |
| **审查 Review** | 对照硬约束与规范复核 | 审查结论（通过 / 待改项） |
| **文档 Docs** | 更新 `MEMORY.md`、看板与相关文档 | 文档 diff |

---

## 2. 并行边界（防覆盖的硬规则）

1. **同一文件同一时间只允许一个 agent 写**。Lead 分配任务时按文件/目录切分，禁止两个任务写入同一文件。
2. **热点文件串行**：`public/app.js`、`public/index.html`、`worker/index.js`、`public/quiz-*.json` 属于高冲突文件，默认串行；确需并行时先拆到不同函数/不同章，再分别提交。
3. **数据文件按章切分**：题源（`quiz-N.json`）、词库（`data-N.json`）可按章并行，互不冲突。
4. **提交即锁**：每次提交一个逻辑改动，commit message 带 scope（见 `AGENTS.md` §6）。同一文件后续改动必须基于最新 `main`。
5. **禁止跨 agent 静默重构**：要动别人的代码（尤其是被正则断言的片段）必须在看板登记并同步改测试。

---

## 3. 任务卡（Lead 派活的最小单位）

派活必须给任务卡，**不允许只给一句话需求**。模板见 `docs/agents/任务卡与交接模板.md`，一张卡至少含：

- 目标（一句话可验收）+ 背景（为什么要做）
- 允许写入的文件白名单（以及"不要碰"的黑名单）
- 涉及门禁（跑哪些命令算完成）
- 验收标准（可观测的结果，例如"答对后停留本题且辨析卡出现 3 条以上"）
- 依赖与阻塞关系、预计影响面

---

## 4. 接力（Handoff）协议

**触发**：换人、换会话、暂停、任务卡完成但后续还有依赖时。

**交接方必须留下**（写入 `docs/agents/接力看板.md` 或直接回复）：

1. 已完成内容（改动文件 + 关键函数/行）
2. 门禁结果（哪个命令、通过/失败、失败点）
3. 未竟事项与已知风险（含"我试过但放弃了"的方案，避免重复踩坑）
4. 下一步建议（接手方可以直接照做的第一件事）
5. 需要接手方先读的文档（L1 表定位）

**接手方必须做**：

1. 读 `MEMORY.md` 顶部最新条目 + 看板当前任务
2. `git status` / `git diff` 确认实际改动（**以代码为准，不信口头描述**）
3. 先跑一遍相关门禁确认基线是绿的，再动手

**铁律**：交接不留可验证产物 = 未完成。口头"差不多了"不算交接。

---

## 5. 完成定义（DoD，逐条打勾）

- [ ] 代码改动完成，且**只**改了任务卡白名单内的文件
- [ ] `npm test` 全绿（215 项）
- [ ] `npm run check` 全绿（66 项）
- [ ] 动过题源 → `npm run quiz:check` 通过
- [ ] 动过后端/同步 → `npm run e2e`（需 dev 服务）
- [ ] 动过界面 → `npm run smoke`（本地）或 `npm run verify:live`（部署后）
- [ ] 遵守硬约束清单（`AGENTS.md` §4）12 条
- [ ] 更新了 `MEMORY.md`（追加顶部条目）与看板状态
- [ ] commit message 符合 Conventional Commits

---

## 6. 冲突与回滚

- 冲突时 **以门禁结果和测试为准**，不以"谁写得多"为准。
- 回滚优先用 `git revert` 保留历史；不要 `reset --hard` 抹掉别人的提交。
- 数据文件（题源/词库）改动量大，**改前确认该文件没有被其他任务占用**（看板里标记）。

---

## 7. 沟通格式（agent 之间）

统一用结构化文本，避免长篇散文：

```
【状态】进行中 / 阻塞 / 已完成
【改动】文件:函数 —— 一句话说明
【门禁】npm test ✅210 / npm run check ✅60 / quiz:check ✅
【风险】…
【下一步】…
```
