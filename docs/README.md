# docs · 文档索引与文档规范

> 目标：**不让任何 agent 或新人为找信息而全量阅读仓库**。按层级取用，按需深入。
> 本文件是**文档的唯一目录**；新增文档必须在此登记，否则等于不存在。

## 0. 先读哪一份（决策树）

```
第一次进仓库 / 每次接任务   → 根目录 AGENTS.md（三层读取法 + 硬约束）
想知道"东西都放哪、能不能动" → docs/目录结构.md（分层表 + 依赖方向）
想知道"现在什么状态、最近改了什么" → 根目录 MEMORY.md（最新在最上面）
想知道"改 X 该看哪些文件"   → docs/agents/模块地图.md
要多人/多 agent 一起干活    → docs/agents/协作与接力规范.md + 任务卡与交接模板.md + 接力看板.md
要改认词题源               → docs/选择题资料生成规范.md（v1.2，权威）

要导入新词书 / 跑题源管线     → docs/词汇书导入与题源生成指南.md
```

## 1. 单一事实源（避免两处说法打架）

同一件事只在一处定义，其余地方**引用而非复述**；冲突时按下表的"权威"一列为准。

| 主题 | 权威文档 | 引用它的地方 |
| --- | --- | --- |
| 界面 / 设计系统 | `设计规范.md` | `AGENTS.md` §4、`项目规范.md` §1.2、`模块地图.md` |
| 认词题源与辨析 | `选择题资料生成规范.md` | `项目规范.md` §5（摘录）、`词汇书导入与题源生成指南.md` |
| 代码 / 测试 / 提交 / 发布 | `项目规范.md` | `AGENTS.md` §4（速查版，冲突以项目规范为准） |
| 项目状态与历史 | 根目录 `MEMORY.md` | `.workbuddy/memory/MEMORY.md`（同步副本） |
| 文档本身怎么管 | 本文件 | — |

**硬约束清单**只在 `AGENTS.md`（速查，L0 必读）与 `项目规范.md`（展开，权威）各出现一次，
其余文档一律写"见 `AGENTS.md` §4"，不复制条文。

## 3. 文档规范（新增 / 修改文档时遵守）

### 3.1 分类与命名

| 类别 | 放哪 | 命名 | 生命周期 |
| --- | --- | --- | --- |
| 规范 | `docs/` | `<主题>规范.md` | 长期有效，版本化（标题写当前版本，如"v1.2"） |
| 计划 | `docs/`（执行中）→ `docs/archive/`（完成后） | `<主题>计划.md` | 完成后归档，归档时把常青部分抽成规范 |
| 报告 / 审计 | `docs/archive/` | `<对象>报告.md` / `质检报告-<对象>.md` | 快照，结论失效即归档 |
| Agent 文档 | `docs/agents/` | 固定名（模块地图 / 协作与接力规范 / 任务卡与交接模板 / 接力看板） | 常青 |
| 记忆 | 根目录 `MEMORY.md`（+ `.workbuddy/memory/`） | 固定名 | **倒序追加，最新在最上面** |

### 3.2 结构模板

每份规范类文档至少包含：

1. **一句话定位**（给谁看、解决什么）+ **适用范围 / 不适用范围**
2. **正文规则**（可判定的条款，写"必须 / 禁止 / 建议"，并注明哪些是机器可判）
3. **验收与门禁**（跑哪个命令；人工清单）
4. **变更记录**（**倒序，最新在最上面**，写明版本 / 日期与影响）

### 3.3 更新纪律

- **代码改动 → 同步更新**：改了行为就要改对应文档；只改代码不改文档视为未完成（见 `agents/协作与接力规范.md` DoD）。
- **改规范 → 同步改校验器与版本号**：题源规范升版必须同步 `scripts/quiz-lib.mjs` 的 `QUIZ_SPEC_VERSION`、
  各 `public/quiz-N.json` 的 `spec` 字段，并跑 `npm run quiz:check`。
- **记忆文件追加不覆盖**：`MEMORY.md` 新条目插到「变更时间线」最顶部；不删历史条目（历史即证据）。
- **归档不删除**：完成 / 失效的文档移入 `docs/archive/`，在**顶部标注"已归档 / 已过时"**并在本索引登记，不要直接删。
- **文件名谨慎改**：`docs/选择题资料生成规范.md` 被 `scripts/check.mjs` 硬引用；改名会让 `npm run check` 失败。
- **中文书写，术语可保留英文**：如 kind、rev、LWW、DoD、Handoff、tokens。

### 3.4 文档 Owner 与评审

- 规范类文档改动需在 commit 中说明理由；影响门禁的必须同步改脚本并跑对应命令。
- 计划 / 报告类文档结论若与代码不符，**以代码为准**，并在文档顶部注明"已过时，见 archive"。
