# 项目规范（代码 · 提交 · 发布 · 数据）

> 适用：所有改动本仓库的人与 agent。
> 与 `AGENTS.md` 的关系：**那里是速查版（L0 必读的雷区清单），这里是权威展开**。
> 两处条文若冲突，**以本文件为准**，并顺手改掉另一处（见 `docs/README.md` §1 单一事实源）。
> 视觉/设计系统不在此处定义，见 `docs/设计规范.md`；题源规则见 `docs/选择题资料生成规范.md`。

## 1. 代码规范

### 1.1 模块边界（前端无框架，靠约定分层）

| 层 | 文件 | 允许 | 禁止 |
| --- | --- | --- | --- |
| 纯逻辑 | `core.js`、`quiz.js` | 纯函数、可注入 rng、无 DOM | `document` / `window` / 全局状态 |
| 页面状态机 | `app.js`、`lecture.js`、`admin.js`、`报告.js` | DOM 与业务状态 | 可复用纯逻辑（应下沉） |
| 组件 | `ui.js` | toast / 对话框 / 图标 / 主题 / 焦点陷阱 | 页面专属业务 |
| 存储 | `idb.js`、`star-store.js` | 读写封装 | 业务判断 |

- `app.js` 已偏大（约 3900 行）：新增**纯逻辑**优先放 `core.js`/`quiz.js`；新增**面板/抽屉**优先抽成独立模块，不要再堆进 `app.js`。
- 异步函数跨账号/跨会话时，必须走会话守卫（`sessionGuard.capture` + `isCurrent()` 早退），参考 `switchPractice` / `flush` / `applyUser` 三处既有实现。

### 1.2 样式

- 颜色**只能**用 `tokens.css` 的语义变量（`--surface`、`--text-2`、`--accent` …），**禁止裸 hex**（`npm run check` 会拦）。
- 双主题（浅/深）都要求 ≥4.5 对比度；新增色值必须过对比度门禁。
- 动效受 `prefers-reduced-motion` 约束。
- 排版 / 色彩 / 图标 / 动效的完整定义见 **`docs/设计规范.md`**（唯一事实源）；本文件不复述。

### 1.3 图标与文案

- 结构性图标一律内联 SVG sprite（`ui.js` 的 `icon()` / `iconHTML()`），**禁止 emoji**。
- 用户可见文案（辨析、提示、错误说明）**禁止硬截断**（`slice + …`）；需要限长时设上限并在生成侧保证句子完整。

### 1.4 数据文件

- `public/data-N.json`（词库）是唯一数据源；`chapters.js` 由 `npm run build:data` 生成，禁止手改。
- `public/quiz-N.json`（题源）必须经 `scripts/quiz.mjs` 校验与 merge 收口；**禁止脚本事后只替换 `text`**。
- `public/quiz-index.json` 由 `npm run quiz:check` 生成，不要手改。

## 2. 测试规范

| 层 | 命令 | 要求 |
| --- | --- | --- |
| 单元 | `npm test` | 215 项；纯逻辑改动**必须**补用例 |
| 静态一致性 | `npm run check` | 66 项；改前端/题源/词库必跑 |
| 题源 | `npm run quiz:check` | 改 `quiz-*.json` 必跑 |
| 题源截断扫描 | `npm run quiz:scan:truncation` | 题源大改后（**诊断工具，不阻断门禁**：FLAGGED 应清零） |
| 接口 | `npm run e2e` | 改 `worker/index.js` / 同步协议必跑（需 dev 服务） |
| 浏览器 | `npm run smoke` | 改界面交互必跑（**只跑本地**） |
| 线上 | `npm run verify:live` | 部署后只读核验 |
| 视觉/无障碍 | `npm run ui:baseline` / `npm run a11y` | 大改视觉时 |

**写测试的硬要求**

1. 涉及日期的用例必须传固定 `nowRef`（`recordDaily(daily, today, nowRef)`），禁止依赖真实系统日期。
2. `test/frontend-guards.test.js` 用**正则断言** `app.js` 源码片段来守护异步守卫；重构被断言的代码时必须同步更新正则。
3. 新逻辑优先写成可单测的纯函数（`core.js` / `quiz.js`），再在页面里调用。

## 4. 发布规范

1. 涉及数据库：**先** `npm run db:migrate`（线上库），**再** `npm run deploy`。顺序反了会全线 500。
2. 已应用的迁移（`migrations/000N_*.sql`）**不可修改**，需要变更就新增 `000N+1_*.sql`。
3. 本地：`npm run db:migrate:local` 后才能 `npm run dev` 跑 e2e/smoke。
4. **前端资源有构建步骤**：`npm run build:assets`（esbuild 压缩 + 内容指纹）产出 `public/dist/` 并改写 HTML 引用。
   `npm run dev` 有 `predev` 钩子、`npm run deploy` 显式串了构建，正常流程不用手动跑；
   但**手工 `wrangler deploy` 会漏掉构建** → HTML 指向不存在的产物 → 整站白屏。
   `npm run check` 第 10 节会比对 `manifest.json` 里的源码指纹，源码改了没重建会告警。
   `public/dist/` 走 `.gitignore` 的 `dist/` 规则，不入库、**禁止手改**。
5. 改前端静态资源后递增 `public/sw.js` 的 `VERSION`，否则老用户仍走缓存。
   `npm run check` 第 9 节会拿 git 改动做比对（工作区 + 上一个提交），只动静态资源未动 sw.js 时告警（warning 级，不阻断）。
6. push 到 `main` 即触发自动部署（约 1 分钟）；部署后跑 `npm run verify:live` 收口。
7. 密钥一律走 `wrangler secret put`（如 `ADMIN_TOKEN`）；禁止入库，`.dev.vars` 已在 `.gitignore`。

## 5. 题源专项规范（摘录，权威见 `docs/选择题资料生成规范.md`）

- 干扰项六类 `kind`：root / form / pos / sense / topic / antonym，有配额与红线；反向（rev）禁用 sense / pos。
- 辨析 `why` 与记忆 `note` 上限 **120 字**（`scripts/quiz-lib.mjs` 的 `WHY_MAX` / `NOTE_MAX`），**不得硬截断**（禁止 `slice + …`）。
  校验器不判截断痕迹，用 `npm run quiz:scan:truncation` 扫描嫌疑项。
- 新增/修改题源流程：`quiz.mjs prompt` → 模型产出 → `quiz.mjs merge`（先校验）→ `quiz:sample` 人工抽查 → `quiz:check` + `npm run check` 门禁。
- 一次性修复脚本放 `scripts/`，命名 `fix-<对象>.mjs`，脚本内必须做前缀/语义校验，禁止无校验的批量替换。

## 6. 目录使用规范

完整分层与依赖方向见 **`docs/目录结构.md`**（唯一事实源），本表只是纪律速查。

| 目录 | 用途 | 纪律 |
| --- | --- | --- |
| `_archive/` | 一次性脚本与证据，分 `length-fix/`（长度修复运动）与 `quiz-fix/`（题源整改运动） | **禁止运行**；见 `_archive/README.md` |
| `_audit/` | 审计与独立复核脚本（`indep/` 下 s1~s9）；报告产物不入库 | 只读；**生产代码禁止 import** |
| `_backup/` | 本地备份快照（未入库） | 勿改、勿依赖 |
| `content/quiz/` | 题源合并前的中间分片 | 合并后保留作溯源，**不是运行时数据源** |
| `shots/` | 视觉回归与复查截图 | `baseline/` 入库，`current/` 与根目录 png 不入库 |
| `scripts/` | 工具链（`quiz-lib` 纯逻辑 / `quiz-data` 数据层 / `quiz*.mjs` CLI / 门禁脚本） | 新增纯逻辑放 `quiz-lib`、需要读词库的放 `quiz-data`，不要在 CLI 里重复实现 |

一次性修复脚本放 `scripts/`，命名 `fix-<对象>.mjs`；**跑完即归档**到 `_archive/`（避免 scripts 里堆积一次性脚本）。

> **例外（可留作模板复用）**：带严格校验（前缀/语义比对、宁缺毋滥）且同类修复仍会再来的脚本，
> 可以留在 `scripts/`，但**必须在文件头注明「已跑完 N 条，保留作同类修复模板」**并写清适用条件。
> 现役例子：`scripts/fix-truncated-why.mjs`（已按模板反推补全 1561 条辨析，题源再出现同类截断时要复用）。
> 不留模板的（一次性、无复用价值）仍按上一行归档。

## 7. 违规处理

- 门禁红 = 未完成，不得交接、不得部署。
- 发现规范与代码冲突：**以代码为准**，并修规范或修代码，二选一，提交信息里说明理由。
- 任何"绕过门禁"的做法（跳过迁移、跳过校验、强推 main）都需要在 `MEMORY.md` 记录原因与回滚方案。
