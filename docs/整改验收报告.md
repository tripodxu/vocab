## 3. 第三期：反向认词（看中文选英文）

按《优化计划.md》§13-17 逐步实现并逐项验收：

- `quiz.js` 方向化：`questionKey` 带方向、反向 answer=英文词、反向兜底排除 sense 类、
  why 讲出错误单词含义；`normalizeCuratedDistractors` 支持 `rev`。
- schema 1.1：`item.rev`（text=英文词，可选 gloss）；校验器 rev 侧规则
  （纯拉丁、屈折排除、词义互含判错、kind 禁 sense/pos、配额）；`quiz-index.json` 记录 revCoverage。
- 交互：`看中文`档（随机=三向混合）、题干大字中文、作答前隔离英文词与发音（空格/再读双防泄底）、
  方向感知文案与样式。
- **反向题源自产**：`quiz-rev-generate.mjs`（全词库 root/form/topic + 弱形近放宽 + 章内频次上限 +
  长度对冲），覆盖 **3555/3568 词**（12 词无可辨析候选，走同章词兜底），校验 0 error，
  答案最长率 9.7%，正向内容逐字未动。

## 5. 残留（警告级，机器不可约，已记录于 README）

- 约 182 条长度比 2.0~2.5 倍：集中在超短释义词（如"现象"），topic 限同章导致短候选不足；

复查入口：`node scripts/quiz-flag.mjs`（逐题标签）→ `node scripts/quiz-fixlist.mjs`（修复清单）。

## 6. 流程纪律（从本报告起生效）

1. **禁止任何脚本事后只替换 `text`**——text/why/kind/note 必须同一次产出（规范 §4.5 红线）；
2. 一切题源变更必须经 `quiz.mjs merge` 校验门禁写入 `public/`，禁止直改发布文件；
3. 新发现的模板句先进 `quiz-lib.mjs` 黑名单再修数据（黑名单是已知模式集合，非完备判据）；
4. 语义新判据必须先标定误报率再设为门禁（"长度修复运动"的教训）。
