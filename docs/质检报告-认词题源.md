# 认词题源（生成的资料）质量审核报告

> 审核对象：`public/quiz-1..22.json`（22 章 / 3568 词 / 10704 个干扰项）及其生成链路
> 审核依据：`docs/选择题资料生成规范.md` v1.0、`scripts/quiz-lib.mjs` 校验器、`public/quiz.js` 兜底算法
> 审核日期：2026-09-19　审核方式：机器校验 + 全量静态扫描 + 人工抽样复核
> 复现脚本：`_audit/`（`final.mjs` / `ambig.mjs` / `strict.mjs` / `recover.mjs` 等，只读，可重复运行）

---

## 0. 一句话结论

**覆盖率与形式合规做到了 100%，但"辨析"这一核心价值的实际可用率大约只有 80%，
其中约 830 条是可机器确证的脚本模板句、约 700~900 条是"解释在讲另一个词"的错位，
另有 49 条错误选项在语义上就是正确答案。** 造成这些缺陷的主因不是模型，而是**事后用脚本批量"修长度"**：
脚本把干扰项的 `text` 换掉却保留了原来的 `why` 和 `kind`。同时工作区里 `public/quiz.js`
有一处未提交的回归，使 `npm test` 红了 14 项、并打穿了"题源缺失也不会坏"的兜底保险。

## 1. 门禁现状（先说结论：三道门禁里有一道是红的）

| 门禁 | 命令 | 结果 |
| --- | --- | --- |
| 静态一致性（42 项） | `npm run check` | ✅ 42/42 通过 |
| 题源校验 | `node scripts/quiz.mjs check` | ✅ 0 error，但 **1364 条长度警告** + 12 条 why 复用警告 |
| 单元测试（88 项） | `npm test` | ❌ **14 项失败**（`ReferenceError: rng is not defined`） |

- 覆盖率：**3568/3568（100%）**，22 章全部进入 `public/quiz-index.json`，无缺口。
- 题源校验器只查"形式"（条数、kind 合法、子串包含、字数、配额），
  **上面报告里的语义缺陷它一条都抓不到**——这正是本报告要补的部分。

### 1.1 顺带发现的代码回归（P0，独立于资料质量）

`public/quiz.js` 是**未提交的工作区改动**（`git status` 显示 `M public/quiz.js`），
在 `classifyDistractor()`（第 256 行签名没有 `rng` 参数）里调用了 `rng()`（第 304、321 行）：

```
✖ pickDistractors：数量正确、不重复、不与正确释义冲突
✖ buildChoiceQuestion：真实的 22 章词库都能出题（不抛错、选项合法）
... 共 14 项
ReferenceError: rng is not defined
    at classifyDistractor (public/quiz.js:321:40)
```

影响面比"测试红"更大：`classifyDistractor` 是**没有精编题源时的兜底出题路径**。
而 `quiz:mjs check` 的容错设计是"某章校验失败 → 从清单剔除 → 前端退回自动兜底"，
所以**今后任何一次题源校验失败，都会让那一章的认词练习直接抛错**，
而不是像 `README` 承诺的那样"功能永远可用"。

## 2. 缺陷清单（按严重度）

### P0-1　机器模板 why：828 条（7.7%）——脚本产物直接显示给学生

`public/app.js:1131` 与 `:1176` 会把 `option.why` 作为「辨析：…」渲染出来，所以下面这些都是**学生真的会看到**的句子：

| 条数 | 原文形态 | 来源脚本 |
| ---: | --- | --- |
| 203 | `星系；[the G-] 银河系≠地球的；（动植物）陆地的\|长度修复\|避免最长项可猜` | `scripts/fix-length.mjs` `makeWhy()` |
| 284 | `engagement 词性不同` | `content/quiz/generate-fix.mjs` `generateWhy()` |
| 241 | `successor 与 herald 意思有区别` | 同上 |
| 76 | `"benefit"与"fund"形近易混，但实际含义不同` | `generate-fixes-v2.mjs` |
| 24 | `"人员，职员；人事部门"属于同一语义场，但具体所指不同` | 同上 |

- 这些字符串里 203 条的 `\|长度修复\|避免最长项可猜` 是**调试标记泄露到生产内容**。
- 其余 601 条虽然格式像人话，但**信息量为零**："X 与 Y 意思有区别"没有说明差在哪，
  正是规范 §5.1 明令禁止、并在附录 A 列入黑名单的写法——
  黑名单只写了 `/但意思不同$/`，被"意思**有区别**"绕过了。
- 分布极不均：ch21 有 354 条、ch20 106、ch5 90、ch19 51、ch18 50、ch7 48、ch4 45、ch16 43。

### P0-2　辨析与所挂选项错位：可机器确证 916 条（8.6%），估计真实量 700~900 条

**根因（已定位到行）**：`scripts/gen-length-fix.mjs:100-104`

```js
newDistractors.push({
  text: replacement,   // ← 换成了另一个词的释义（只为凑长度）
  kind: d.kind,        // ← kind 跟着 text 一起失真
  why: d.why           // ← 却保留了原来那句辨析
});
```

**直证（ch1 #1 `atmosphere`，正确释义「大气层，大气圈；气氛」）**

| | 原始模型分片 `content/quiz/1.json` | 已发布 `public/quiz-1.json` |
| --- | --- | --- |
| 干扰项 2 | `岩石圈`　why：`litho- 是石，指地壳岩石部分` ✅ | `爆发，喷发；突然出现`　why：`litho- 是石…` ❌ |
| 干扰项 3 | `半球`　why：`hemi- 是一半，与气体无关` ✅ | `地震的，地震引起的`　why：`hemi- 是一半…` ❌ |

即：**原始产出是对的，是"长度修复"把它改坏了**——学生选了"爆发，喷发"，
屏幕上给出的解释却在讲"岩石圈"。

**量化**（最严口径：辨析里的英文词全部能在词库中认出、但没有一个对应这个选项）：

```
可自动确证 916 / 10704（8.6%）
含词库外英文词、无法自动判定 1211 条（人工复核 28 条抽样中约 40% 属实）
→ 真实错位量估计 700~900 条（约 7%~9%）
```

| ch2 #48 bud | 光合作用 | `flower 是已开放的花，bud 是未开放的蕾` |

### P0-3　硬歧义 49 条（0.5%）：错误选项在语义上就是正确答案

校验器只做"拼接后**子串**包含"，抓不到"义项集合被答案覆盖"（换个顺序、换个标点就漏）。
按义项集合判定后，有 49 条属于**选了也对**：

| 位置 | 正确释义 | 被当成错误的选项 |
| --- | --- | --- |
| ch9 #18 anticipate | 预期，预料 | 预料，预期（= `expect` 的释义） |
| ch9 #19 expect | 预料，预期 | 预期，预料（= `anticipate` 的释义） |
| ch22 #32 prior / #34 preceding | 在先的，在前的 | 在前的，在先的（互为对方选项） |
| ch10 #117 canvas | 帆布；油画布 | 画布；油画布 |
| ch10 #133 miniature | 微型的，很小的 n. 缩微模型；微型画 | 很小的；微型的 |
| ch18 #143 mislead | 误导，欺骗，使误入歧途 | 误导，使误入歧途 |
| ch1 #168 remote | 遥远的；偏僻的；疏远的 | 遥远的；疏远的 |

另有 **346 条（3.2%）** 属于近义改写（义项重合 ≥50%），如
`ch5 #49 excellent` 的选项「突出的，杰出的」对上 `outstanding` 的释义；`ch12 #38 glass` 的选项「杯子」。
这些不算硬错，但同样削弱了区分度。

### P1-4　41% 的选项释义无法追溯到词库原释义

规范 §4.3 要求"干扰项 text 应当是词库里真实存在的词的中文释义（优先同章）"：

```
选项释义 == 词库原释义（逐字相同）   4371 / 10704（40.8%）
同章近似改写（可追溯）              1948（18.2%）
完全无法追溯                       4385（41.0%）
```

抽样看，无法追溯的多是**合理改写或词库外同层词汇**（`考古学家`、`园艺师`、`跳蚤`、`小腿`、`旋律；曲调`），
不是胡说；但由此带来两个实际后果：
1. "4 个选项同一层级"只能靠人眼保证；
2. 校验器/兜底算法赖以判歧义的"释义归一化比对"在这些选项上**失效**（P0-3 就是这么漏过去的）。

### P1-5　万能干扰项（同章内反复使用同一个错误选项）

| 章节 | 同一个释义被当作干扰项的次数 |
| --- | --- |
| ch5 | `事件~s公共事务政治事务` **20 次**、`知识学识知悉` 16 次、`主要的最初的小学教育的` 15 次 |
| ch2 | `呼吸` 16 次、`开垦开拓利用` 11 次 |
| ch3 | `发源来自创始` 15 次 |
| ch9 | `排练` 15 次、`广播员播音员` 10 次、`电影` 10 次 |

全库出现 ≥8 次的有 15 种以上。规范 §4.2 第 4 条明确禁止"同一批题里反复用同一个万能干扰项"，
但没有任何校验。

### P1-6　`kind` 标注不可靠（次要，但会影响界面标签与统计）

大部分标注是可辩护的，但有确凿反例：`ch22 #1 daily` 的干扰项「每周的；周刊」（weekly）标成
`form`（形近/音近），而 `daily` / `weekly` 只共享词尾 `ly`，按规范 §4.1 的阈值（前缀 ≥3 或后缀 ≥4）
并不成立，正确标签应是 `topic`/`sense`。
更普遍的情况是 P0-2 的连带伤害：`text` 被换掉而 `kind` 保留，标签随之失真。

## 3. 关键判断：那场"长度修复"得不偿失

`content/quiz/` 里的原始模型分片**覆盖 100%（3568/3568，零缺口）**，我做了 A/B 对比：

| 指标 | 当前 `public/quiz-N.json` | 只合并原始分片（撤掉所有 `*-fix-*`） |
| --- | ---: | ---: |
| 覆盖率 | 3568 词 | 3568 词（无损） |
| **机器模板 why** | **828** | **0** |
| 硬歧义（选项=答案） | 48 | 49 |
| why 与选项错位 | 17.6% | 17.8% |
| 长度比不合格 | 1364 | 3096 |

结论有三点：

1. **回退低风险、收益明确**：能一次性清掉全部 828 条模板句，且覆盖率零损失。
2. **但回退不等于治好**：错位率与歧义率几乎不变——说明**"辨析讲错词"有一半以上是原始生成就有的问题**，
   不是修复脚本单独造成的。
3. **修复运动的真实取舍是**：用"必然更差的辨析 + 泄露的调试标记"换"更整齐的选项长度"，
   而长度只是**外观性**指标。这笔交易是亏的。
