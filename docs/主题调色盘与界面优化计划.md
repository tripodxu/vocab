# 主题调色盘与界面优化计划（第四期）

> 立项：2026-09-20，用户需求原话："主题色可以是一个调色盘，让用户选"。
> 状态：**计划中（未开始）**。本文档是可执行设计——落点全部对准现有代码，按阶段实施即可。
> 前置事实：天蓝换肤已完成（提交 `b86d7b9`），全站视觉变量已收敛到 `public/tokens.css` 单文件
> （`:root` 浅色 + `[data-theme="dark"]` 深色两块，渐变已 token 化为 `--accent-grad`）。

## 0. 一句话结论

把"天蓝"从一个写死的主题色，升级为**六选一的用户调色盘**：`tokens.css` 里的 accent 系变量
按 `data-accent` 属性分块定义，用户在设置面板选色后写入 `settings.accent`（随云端同步），
两页共用的外观应用逻辑立即生效；favicon 与安装图标的品牌渐变保持天蓝不变（品牌识别与用户个性分离）。

## 2. 方案：`data-accent` 属性 + 六个精调调色盘

### 2.1 架构选型

**选 CSS 属性块（方案 A）**：`tokens.css` 内为每个调色盘写一个
`[data-accent="emerald"]` / `[data-accent="emerald"][data-theme="dark"]` 覆盖块；
JS 只负责设置 `document.documentElement.dataset.accent`。
不选"JS 注入变量"（方案 B）——它需要 head 内联脚本（CSP 禁内联）或有首帧闪烁风险。

soft / faint / glow 三类透明度变量**保留手写 rgba**，不用 `color-mix` 派生——
六个盘都要人工核对对比度，显式写值才能逐个验收。

### 2.2 六个调色盘的精调值（可直接照抄进 tokens.css）

每个盘两主题各 7 个变量：`accent / accent-strong / accent-ink / accent-grad / accent-soft / accent-faint / glow`，
外加 `bg-glow-1 / bg-glow-2`（页面光晕）。色值取自 Tailwind 色阶并已按对比度调整。

| 盘 | 主题 | accent | strong | ink | grad（135deg 三站） | glow 透明度基色 |
| --- | --- | --- | --- | --- | --- | --- |
| **sky 天蓝（默认）** | 浅 | #0284c7 | #0369a1 | #fff | #0ea5e9 → #0284c7 → #1d4ed8 | rgba(14,165,233) |
| | 深 | #38bdf8 | #7dd3fc | #062033 | #7dd3fc → #38bdf8 → #0ea5e9 | rgba(56,189,248) |
| **violet 紫罗兰（经典）** | 浅 | #7c5cfc | #6a48e8 | #fff | #7c5cfc → #8b5cf6 → #d946ef | rgba(124,92,252) |
| | 深 | #9b85ff | #b3a2ff | #120c2b | #b3a2ff → #9b85ff → #c084fc | rgba(155,133,255) |
| **emerald 翡翠** | 浅 | #059669 | #047857 | #fff | #10b981 → #059669 → #0d9488 | rgba(16,185,129) |
| | 深 | #34d399 | #6ee7b7 | #022c22 | #6ee7b7 → #34d399 → #14b8a6 | rgba(52,211,153) |
| **rose 玫瑰** | 浅 | #e11d48 | #be123c | #fff | #fb7185 → #e11d48 → #be185d | rgba(244,63,94) |

配套值（每盘同主题）：`accent-soft = accent 的 14%（浅）/20%（深）alpha`、`accent-faint = 6% / 9%`、
`glow = 0 6px 20px + glow 基色 32%（浅）/ 45%（深）`、`bg-glow-1 = 18% / 22%`、
`bg-glow-2 = 青色辅光 rgba(34,211,238,0.10)`（sky/violet 盘可用各自的辅光，保持现在的层次感）。

### 2.3 对比度验收基线（每个盘上线前必须过）

- 浅色：`accent` 作按钮底配白字，与白的对比度 ≥ 3.0（按钮文字 800 加粗大字）；作正文文字色时 ≥ 4.5。
  上表浅色 accent 全部 ≥ 4.0（amber #d97706 为 3.6，仅用于大号加粗场景，正文场景用 strong #b45309 = 5.0）。
- 深色：`accent` 在 `--bg` 上 ≥ 7.0；`accent-ink` 在 `accent` 上 ≥ 7.0（深色盘的 ink 都是深色调）。
- 渐变三站的**最浅站**与 `accent-ink` 的对比度 ≥ 3.0（渐变按钮的最亮角是可读性最差点）。

## 3. 交互设计：设置面板的"外观"分组

### 3.1 布局（设置抽屉顶部新增"外观"组，原"练习方式"上移合并）

```
外观
├─ 主题模式      [跟随系统 | 浅色 | 深色]        ← 现有控件，位置移入本组
└─ 主题色        [●天蓝] [●紫罗兰] [●翡翠] [●玫瑰] [●琥珀] [●石板]   ← 新增色卡网格
```

### 3.2 色卡网格组件（`buildSwatches`，放 `ui.js` 与 buildSeg 并列）

- 每个色卡：36×36 圆角方块，背景 = 该盘的 `accent-grad`，选中态 = 外圈 2px `--text` 描边 + `aria-pressed`；
- 键盘可达：`role="radio"` + 方向键（复用焦点陷阱组件的惯例）；
- 点击即生效（无需保存按钮）：写 `settings.accent` → `markSettingsDirty()` → `applyAccent(value)`；
- 悬浮显示盘名（`title` + `aria-label`）。

### 3.3 应用逻辑（两页共用，放 `core.js` 导出）

```js
// core.js 新增导出：两页共用；app.js 选色时调用，lecture.js 启动时调用
export function applyAccent(value, root = document.documentElement) {
  root.dataset.accent = ACCENTS.includes(value) ? value : "sky";
}
```

- `app.js`：启动时 `applyAccent(settings.accent)`；色卡点击后即时调用；
- `lecture.js`：启动时从 localStorage 读同一份设置（`vocab:v3:guest` / `vocab:v3:u<id>`，
  复用现有键规则）应用；并监听 `storage` 事件——刷词页换色、讲义页切过去立刻同步；
- `<meta name="theme-color">` 随 主题×调色盘 组合更新（浅色=各盘的页面底色不变，
  深色=#0a0d19 不变——theme-color 跟随主题模式而非调色盘，行为最不易翻车）。

### 3.4 设置模型

- `core.js` normalizeSettings 白名单新增：`accent: ACCENTS.includes(src.accent) ? src.accent : "sky"`；
- 云同步零改动（settings 对象整体上行/下行，旧版本读到未知字段会走 normalize 回落，天然向前兼容）；
- **离线游客**同样生效（写本机）。

## 4. 相邻 UI 优化（本计划顺路做掉的四件小事）

| # | 项 | 做法 | 为什么顺路 |
| --- | --- | --- | --- |
| 4-1 | 换色过渡动画 | `html[data-accent]` 变更时给用了 accent 的元素加一次性 `.accent-fade` 类（200ms opacity/背景过渡），避免颜色跳变 | 调色盘的核心体验就是"换着玩"，跳变会显得廉价 |
| 4-2 | 设置面板"外观"组重排 | 主题模式/主题色/音效三组合并为一个视觉分组（组标题 + 卡片底色） | 色卡加入后面板变长，需要层级 |
| 4-3 | 认词选项 hover 态 | `.option:not(:disabled):hover` 加 `--accent-faint` 底色 + 1px accent 描边过渡 | 触屏之外桌面端有可感知的悬停反馈 |
| 4-4 | 讲义页选中态跟随 | 讲义卡片跳转按钮/批注工具的 accent 使用点复查（lecture.css 仅 4 处），确认随盘变化 | 两页必须是同一个产品 |

## 5. 需要先定的 3 个决策

1. **调色盘数量与命名**：建议 6 盘 + 中文色名（天蓝/紫罗兰/翡翠/玫瑰/琥珀/石板）。
   多于 8 个会让色卡网格在移动端折行难看；少于 4 个显得敷衍。
2. **是否提供自定义取色器**（color input → 用户任意色）：建议 **P3 再说**。
   自由取色后 soft/faint/grad/对比度都无法人工预校验，需要 `color-mix` 派生 + 对比度不达标时的
   自动降级逻辑（ink 在黑白之间二选一），是一个独立的、有风险的功能。
3. **favicon / 安装图标是否跟随调色盘**：建议**不跟随**（保持天蓝品牌渐变）。
   图标是桌面/书签里的识别锚点，跟着用户换色反而破坏"这是哪个标签页"的辨识。

- [ ] 六盘 × 两主题 × 两页（刷词/讲义）截图过目，无紫色残留、无对比度翻车点
- [ ] 选色后刷新页面/重启浏览器，选择保持；换账号各自独立（设置随账号走）
- [ ] 云端同步：A 设备换色 → B 设备登录后跟随（settings 同路）
- [ ] `npm run check` 新增对比度与结构校验全绿；`npm test` 全绿
- [ ] `npm run smoke` 新增用例：点色卡 → `data-accent` 变化 + 刷新保持 + 讲义页跟随

- [ ] `prefers-reduced-motion` 下换色无过渡动画（复用现有全局规则）

## 8. 明确不做

- 不做"每盘独立的光晕形状/背景图"——只换色不换版式，保持两页版式唯一来源；
- 不做按调色盘定制插画/配图（配图是讲义内容，不是主题）；
- 不把调色盘塞进首次访问引导（保持首屏零配置即用的原则）；
- 不改云同步协议（settings 整体上行的既有设计足够）。
